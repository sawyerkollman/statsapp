# Stats v1.8 "Monitoring depth" — design

**Date:** 2026-09-02 · **Branch:** `master` (`8b3bf81`, PR #9 merged) → `feature/v1.8-monitoring-depth` · **Status:** approved by owner work order (Batch 2)

## Goal

Turn the severity the app already computes into actionable alerts, make thresholds
editable for every group, give each tile a real time-axis detail chart, and remove the
remaining friction in the tray, overlay, dashboard, and Fans window — while cutting the
per-tick cost of the refresh path. Windows-only; `Stats.Core` is not restructured for
portability.

## Global constraints

- LibreHardwareMonitor is touched only from the poller thread. The fan lock rework
  moves hardware calls *outside* the settings gate but never off the poller thread.
- Fan-control safety invariants (CLAUDE.md rule 6) are preserved verbatim: `InSoftware`
  is set before a write, failure counting and the three-strikes Auto fallback are
  unchanged, `ReleaseLocked` clears tracking only when `SetAuto` succeeds, pumps floor
  at 50 %, ranges are sanitized at discovery.
- Every new `AppSettings` field has a default; `SettingsService.Load` migrations live
  in `ThresholdDefaults.EnsureDefaults`. Old `settings.json` files keep loading.
- `MetricGroup` is append-only and unchanged; `GroupOrder` is unchanged.
- No new NuGet packages. Alert toasts use the existing H.NotifyIcon `TaskbarIcon`
  (`ShowNotification`); sound uses `System.Media.SystemSounds`.
- All new palette references are `DynamicResource` on the existing eleven brushes.
- Build and tests are the automated gate (0 warnings); hardware/visual behavior goes on
  the owner checklist.

## 1. Alerts

### Engine (`Stats.Core/Alerts`)

`AlertEngine` is a pure, clock-injected state machine evaluated once per UI-thread
refresh with the set of *monitored* metrics (union of dashboard and overlay
selections), each metric's current value, and its `Severity`:

- A metric entering `Crit` starts an episode (`CritSince = now`, peak = value).
- While in `Crit` the peak value is tracked. When `now - CritSince ≥ HoldSeconds`
  and the episode is armed, exactly one `AlertEvent` is raised and the episode disarms.
- Leaving `Crit` (Warn or Normal, or a null value) ends the episode: its `Duration` is
  finalized on the log row and the metric re-arms. Flapping in and out of Crit inside
  the hold window raises nothing.
- Metrics that stop being monitored drop their state; the engine holds no threads.

`AlertEvent { DateTime RaisedAtLocal; string MetricId; string DisplayName; float
PeakValue; float Threshold; bool LowerIsWorse; string Unit; }`. The engine exposes
`Tick(IEnumerable<AlertSample>, DateTime nowUtc) → IReadOnlyList<AlertEvent>` and an
`EpisodeEnded` callback carrying the final duration so the log row can be completed.

### Surfaces

- Tray balloon via `_tray.ShowNotification(title: "Stats alert", message: "CPU Package
  96 °C — crit ≥ 92")`. Inverted rules read "crit ≤ 30".
- Optional chime: `SystemSounds.Exclamation.Play()` when `AlertSoundEnabled`.
- **Alert log**: `PeaksWindow` gains a `TabControl` (Peaks | Alerts). The Alerts tab
  lists time, metric, peak value, threshold, and duration (live "ongoing" until the
  episode ends). Session-scoped, newest first, capped at 200 rows.
- Settings → **Alerts**: enable (default on), hold seconds (default 10, 1–120), sound
  (default off).

### Settings

`AlertsEnabled = true`, `AlertHoldSeconds = 10`, `AlertSoundEnabled = false`.
`SettingsChange.Alerts`.

Alerts evaluate regardless of dashboard/overlay visibility (see §10).

### Tests

Enter/hold/raise once; flapping inside hold never raises; re-arm only after leaving
Crit; two metrics independent; hold-seconds change takes effect; unmonitored metric
state is discarded; peak tracking; duration finalization; 200-row cap in the log VM.

## 2. Threshold system rework

### Model and migration

`ThresholdRule` is unchanged. `ThresholdDefaults.Rules()` gains
`{ Motherboard, "°C", warn 80, crit 95 }`; `EnsureDefaults` adds it to old files. CPU
and GPU load already persist as two rows — the coupling is only in the editor — so no
data migration is needed beyond the new default.

### Settings grid

`SettingsViewModel` replaces the five hard-coded warn/crit pairs with
`ThresholdRuleItems` (one `ThresholdRuleItemViewModel` per rule: `Group`, `Unit`,
`Warn`, `Crit`, `LowerIsWorse` read-only display, per-row `Error`). Editing a cell
validates ordering (`warn < crit`, or `warn > crit` when lower-is-worse) and
writes through only when valid; the row shows the error inline otherwise.
"Add rule…" offers the `(group, unit)` pairs present in discovered metrics that have no
rule yet, ordered by `GroupOrder`; adding seeds the row with `0 / 0` for the user to
fill in (nothing applies until valid). Rules are never deleted from the grid — defaults
would only be re-seeded on the next load.

### Per-tile editor

`ThresholdDialog` (Stats.App) replaces the free-text `InputDialog` for thresholds:
two numeric fields labelled Warn/Crit with the unit, a direction note when the
governing rule is lower-is-worse, an explicit **Lower is worse** checkbox when the
group has no rule, an inline validation message (bad input never silently ignored), a
**Clear** button that removes the override, and OK/Cancel. Parsing/validation is pure
Core (`ThresholdInput.TryParse`) and unit-tested. `DashboardViewModel.SetTileThresholds`
takes an explicit `ThresholdRule?` — it no longer guesses direction from a rule that
may not exist.

## 3. Tile detail view

### Gap honesty (prerequisite)

`MetricHistory.Add` always advances the ring buffer: a null/NaN sample stores
`float.NaN` so x is uniform time. Session min/max/avg continue to ignore NaN (they are
only updated for real values — already the case). `ToArray()` may now contain NaN;
`Sparkline` computes its range over finite values only and breaks the polyline/fill
at NaN runs (a visible gap). `MetricHistoryTests` "null/NaN does not advance" cases are
rewritten deliberately to assert the NaN slot.

### Window

`MetricDetailWindow` (one instance, retargetable): opened by double-clicking a tile or
the tile menu's **Details…**. Header shows metric name, current value with severity
colour, and min/avg/max. `HistoryChart` (new `FrameworkElement`) renders the history
with y-axis labels, time-axis labels derived from capacity × poll interval ("−30 m …
now"), warn/crit guide lines from the effective rule/override, NaN gaps, and a hover
crosshair showing value **and time**. `MetricDetailViewModel` (Core, testable)
computes the labels, guide values, seconds-per-sample, and stats from a
`MetricHistory` + `AppSettings`; the window re-reads it on every dashboard refresh
while visible.

## 4. Peaks: timestamps and copy

`MetricHistory` records `SessionMinAtUtc`/`SessionMaxAtUtc` (set alongside
min/max, cleared by `ResetSession`); `MetricStore.Apply` passes the snapshot
timestamp. `PeakRowViewModel` gains `MinAtText`/`MaxAtText` ("at 14:32", local)
shown as subtext/tooltip. `PeaksViewModel.ToTsv()` produces a header row plus
`metric ⇥ now ⇥ min ⇥ min-time ⇥ avg ⇥ max ⇥ max-time` lines; the **Copy** button in
the window calls `Clipboard.SetText` and shows an inline error on failure.

## 5. Tray metric picker

`AppSettings.TrayMetricId` (string?, default null = Auto). Settings → "Tray icon
shows" ComboBox offering **Auto** plus every discovered `°C`/`%` metric.
`TrayMetricSelector.Resolve(id, definitions)` (Core) returns the definition or null
for Auto/missing; App falls back to the existing CPU-temp heuristic. The renderer is
unchanged; the tooltip keeps CPU/GPU temps. `SettingsChange.Tray`.

## 6. Overlay move mode

Tray menu item **Move overlay** toggles move mode: click-through is turned off via
`ClickThrough.Set` directly (the persisted `OverlayClickThrough` is untouched), the
overlay is shown/activated, and `OverlayViewModel.IsMoveMode` draws a dashed
`AccentBrush` outline. Exit via the same menu item (now "Done moving overlay"), `Esc`
on the overlay, or toggling the overlay; exit restores `ClickThrough.Set(overlay,
settings.OverlayClickThrough)`. Session-only state.

## 7. Dashboard interaction polish

- **Drag feedback:** `Tile_DragOver` resolves the source tile's group from the drag
  data; cross-group targets get `DragDropEffects.None` (no-drop cursor). Same-group
  targets show an insertion line (`InsertionAdorner`, `AccentBrush`, left edge of the
  target) that is removed on `DragLeave`/`Drop`.
- **Hover affordance:** a "⋯" button appears top-right on tile hover (template
  trigger) and opens the same context menu; tiles are focusable and `Shift+F10` / the
  Menu key open it too. Menu construction is factored into one method.
- **Commands:** `SetTileKind`, `SetTileSize`, `SetTileMax`, `RenameTile`,
  `SetTileThresholds`, `RemoveTile` become `[RelayCommand]`s taking small parameter
  records (`TileKindEdit`, `TileSizeEdit`, `TileMaxEdit`, `TileRenameEdit`,
  `TileThresholdEdit`, metric id). Behavior is identical; tests execute the commands.

## 8. FPS discoverability

`DefaultSelector` stays unchanged. `AppSettings.FpsHintDismissed = false`. The
dashboard shows a dismissible hint banner ("Gaming? Add FPS, 1% lows and frame time
from ☰ Metrics") when the flag is false, Game metrics were discovered, and none is
selected; **Got it** persists the flag. The picker's Game group header gets the caption
"uses bundled PresentMon; runs only while selected".

## 9. Fans window UX

- **Profile dropdown follows the active profile.** `SyncProfileState` now sets
  `SelectedProfileName` quietly to `ActiveProfile` (null → no selection, header shows
  "Custom"). Picking a different entry loads it. The VM tracks `LastLoadedProfile`;
  `IsModified` is true when a profile was loaded and the controller's active profile
  has since become null (a user edit). A **Reload** button (visible when modified)
  re-applies `LastLoadedProfile`. This replaces the v1.4 deviation that decoupled
  selection from active state.
- **Identify:** `FanController.Identify(channelId, nowUtc)` sets a per-channel
  `IdentifyUntil = now + 2 s`. `Tick` treats an unexpired identify as
  `target = MaxPercent` (ramp limit skipped so the pulse is visible), written through
  the normal `WriteLocked` path; when it expires the channel's own mode resumes (Auto →
  release, Manual/Curve → ramp back). Identify never changes prefs or
  `ActiveFanProfile`. Disabled when fan control is off. Tested: pulse writes max,
  expiry restores prior mode for Auto and Manual.
- **Safety banner:** `AppSettings.FanSafetyBannerCollapsed = false`; **Got it**
  collapses the always-on warning to one line and persists. Recovery/conflict banners
  are unchanged.

## 10. Refresh-path efficiency

- **Fan lock scope.** `FanController.Tick` becomes three phases: (1) under `_gate`,
  compute each channel's decision (`Write(percent)`, `Release(status)`, or none),
  setting `rt.InSoftware = true` and latching the marker *before* leaving the lock for
  any write; (2) outside the lock, perform `SetPercent`/`SetAuto` on the poller thread
  and collect outcomes; (3) under `_gate`, apply bookkeeping exactly as today
  (`LastWritten`, `Failures`, `Status`, three-strikes → `pref.Mode = Auto` +
  `_pendingSave`, `ReleaseLocked` semantics: tracking cleared only on success), update
  the marker, and flush the pending save. `RestoreAll` and `RecoverFromUncleanShutdown`
  are unchanged (they run with the poller stopped). `FanControllerTests` must pass
  unmodified except where they assert lock-holding.
- **History arrays.** `MetricHistory.CopyTo(float[]? reuse)` returns a buffer of
  exactly `Count` samples, reusing `reuse` when its length matches.
  `MetricTileViewModel` alternates two buffers so `HistoryValues` changes reference
  (raising the property change) with zero steady-state allocation once the buffer is
  full.
- **Visibility gating.** The Dispatcher refresh applies the snapshot to the store,
  evaluates alerts, updates the tray, and refreshes Peaks/Fans/Detail when visible; the
  dashboard and overlay VMs refresh only when their windows are visible, and once
  immediately on Show.
- **Coalescing.** The poll-thread handler stores the latest snapshot and posts one
  `BeginInvoke` only when none is pending (interlocked flag); the UI action clears the
  flag and applies the latest snapshot, so a busy UI never accumulates a backlog and
  never processes stale data.
- **Cheap extras.** `ThresholdIndex` (keyed `(group, unit)` lookup) built once per
  `RefreshAll` and used by tiles/overlay/alerts instead of a LINQ scan per metric;
  picker `CurrentText` is set only when it changes.

## 11. Accessibility floor

- `AppSettings.DashboardUiScale = 1.0` (clamped 0.9–1.3 at load). Settings slider
  (`Delay=250`) → `DashboardViewModel.UiScale` → `LayoutTransform` on the dashboard
  content root. `SettingsChange.UiScale`.
- Tiles set `AutomationProperties.Name` from `MetricTileViewModel.AutomationLabel`
  ("<metric>, <value>, <severity>") and show a non-colour glyph next to the value:
  `▲` at Warn, `‼` at Crit (`SeverityGlyph`).
