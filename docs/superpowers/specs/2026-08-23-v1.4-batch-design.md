## 1. Crash-recovery marker

**Problem.** If Stats crashes while a channel is in software mode, the fan stays at the last PWM.

**Design.** `IFanArmedMarker { bool Exists(); void Set(); void Clear(); }` with `FileFanArmedMarker(path)`
writing an empty file `%AppData%\Stats\fans-armed`. `FanController` takes the marker in its constructor:
- `Set()` the first time any channel's `InSoftware` becomes true (tracked by a `_armed` flag; one file write).
- `Clear()` at the end of `RestoreAll()` / `Tick` only when **no** runtime remains `InSoftware` (a failed
  release keeps the marker).
- `RecoverFromUncleanShutdown()`: if `Exists()` → `SetAuto` on **every backend channel** (runtime state is
  lost, so release everything), `Clear()`, return `true`. App calls it right after constructing the
  controller and **before** `_poller.Start()` (single-threaded at that point), and when it returns true
  sets `FansViewModel.RecoveryNotice` = "Stats did not shut down cleanly last time — all fans were returned to
  device control." (shown in the Fans window banner until dismissed; also a Trace line).
- Channels whose pref is still Manual/Curve get re-driven on the first tick as usual (user intent).
- Marker I/O errors are swallowed + traced (never block control).

**Tests.** Fake marker: set on first software write; not set while disabled; cleared by `RestoreAll` when
all released; kept when a release failed; `RecoverFromUncleanShutdown` releases all channels + clears +
returns true; returns false when no marker.

## 2. Detect competing fan software

`ConflictingFanSoftware.Match(IEnumerable<string> processNames) → IReadOnlyList<string>` (friendly names,
deduped, ordered). Known process-name stems (case-insensitive, `.exe` stripped):

| Stem(s) | Friendly |
|---|---|
| `msi center`, `msi.centralserver`, `msi center sdk` | MSI Center |
| `fancontrol` | Fan Control |
| `argusmonitor` | Argus Monitor |
| `msiafterburner` | MSI Afterburner |
| `icue` | Corsair iCUE |
| `nzxt cam` | NZXT CAM |
| `armourycrate`, `armoury crate`, `asusfanservice` | ASUS Armoury Crate |
| `speedfan` | SpeedFan |
| `gigabytecontrolcenter`, `aorusengine`, `gcc` (exact) | Gigabyte Control Center |
| `precisionx_x64`, `precisionx` | EVGA Precision |
| `corsairlink` | Corsair Link |

`IRunningProcesses { IEnumerable<string> Names(); }` — production impl `Process.GetProcesses()` names
(swallow exceptions). `FansViewModel` gets `Func<IEnumerable<string>>` + clock; `Refresh()` re-checks at
most every **5 s**; exposes `ConflictText` ("Detected: MSI Center, Fan Control — two controllers fighting the
same fan is unsafe. Close them before enabling fan control.") and `HasConflict`. Warn only — do **not** block
enabling (vendor tools may be idle). Fans window banner turns the crit colour when `HasConflict`.

**Tests.** `Match` (stems, case, `.exe`, dedupe, unknown names ignored, `gcc` exact only); VM throttle
(two refreshes within 5 s call the process source once); text formatting.

## 3. Surface FPS reader status

`GroupSectionViewModel.StatusText` (string, default ""), `HasStatus`. `DashboardViewModel.SetGroupStatus(
MetricGroup group, string? text)` (no-op if the group has no section). App's Dispatcher tick calls
`_dashboardVm.SetGroupStatus(MetricGroup.Game, FrameStatus())` where `FrameStatus()` = `""` when the reader is
inactive or healthy, else `_frameReader.StatusMessage` shortened for display (first sentence; the MSIX case
already names the cause). XAML: a `TextBlock` under the Expander header (Warn colour, 11 px), collapsed when
`!HasStatus`. Overlay unchanged.

**Tests.** `SetGroupStatus` sets/clears text and `HasStatus`; unknown group ignored; survives
`RebuildSections` (status kept by group).

## 4. Gate motherboard / USB-controller polling

`AppSettings.ReadMotherboardAndCoolers` (bool, default **true**). `LhmSensorReader(bool
motherboardAndControllers = true)` sets `IsMotherboardEnabled`/`IsControllerEnabled` from it. App passes the
setting. `SettingsViewModel.ReadMotherboardAndCoolers` ↔ settings, raises `SettingsChange.Hardware`; App
handles it by setting `SettingsViewModel.HardwareStatus` = "Restart Stats to apply" (no live re-discovery).
XAML: Settings tab → "Hardware" header → CheckBox "Read motherboard fan headers and USB coolers (needed for
fan control; restart to apply)" + status line. When off, the Fans window's unavailable text adds "Enable
'Read motherboard…' in Settings."

**Tests.** Settings default true + round trip; VM change raises `Hardware` and persists.

## 5. Fan profiles

```csharp
public sealed class FanProfile { string Name = ""; Dictionary<string, FanChannelPref> Channels = new(); }
AppSettings: List<FanProfile> FanProfiles = new(); string? ActiveFanProfile;
```
`FanController`:
- `FanProfile SnapshotProfile(string name)` — deep copy of the live `FanChannels` (prefs and point lists
  cloned).
- `void ApplyProfile(FanProfile profile, bool deferSave = false)` — replaces `FanChannels` with deep copies
  (channels absent from the profile are set to Auto), resets every runtime's `LastSourceUsed`/`Failures`,
  sets `ActiveFanProfile = profile.Name`; saves (outside the lock from the UI thread; with `deferSave` the
  save happens at the end of the next `Tick` under the lock — poll-thread callers use this).
- Any `Mutate` (user edit) sets `ActiveFanProfile = null` ("Custom").
- `static IReadOnlyList<FanProfile> CreateDefaultProfiles(IReadOnlyList<FanChannel> channels, string?
  cpuTempId, string? gpuTempId)` → **Silent** `(30,20)(50,30)(70,55)(85,100)`, **Balanced** = default curve,
  **Gaming** `(30,40)(50,60)(70,90)(85,100)`; every non-pump channel is `Curve` with source = `gpuTempId` for
  channels whose `Device` contains "NVIDIA"/"GeForce"/"Radeon"/"RTX"/"RX " (case-insensitive) else
  `cpuTempId`; channels named "pump" stay `Auto`; if the chosen source id is null the channel stays Auto.
`FansViewModel`: `ProfileNames` (ObservableCollection<string>), `ActiveProfileName` (string; "Custom" when
null — display only), commands `SaveProfile(string name)` (overwrite same name), `LoadProfile(string)`,
`DeleteProfile(string)`, `CreateDefaultProfiles()` (adds the three if names don't exist; cpu id = first
`°C` option whose id starts with `cpu.` and contains `tctl`/`package`, else first `cpu.`; gpu id = first
`gpu.` `°C` option containing `core`, else first `gpu.`). Fans window header row: ComboBox (profiles) +
"Save as…" (reuses `InputDialog`) + "Delete" + "Create defaults". Loading a profile refreshes all channel
rows.

**Tests.** Snapshot deep-copies (mutating the snapshot doesn't change live); apply replaces + sets Auto for
missing + resets runtime (`Curve_FollowsSource` re-evaluates immediately); `Mutate` clears `ActiveFanProfile`;
defaults generation (sources, pump Auto, curves); settings round trip; VM save/load/delete/create flows.

## 6. Game-aware profile switching

```csharp
AppSettings: bool GameModeEnabled; string? GameModeGamingProfile; string? GameModeDesktopProfile;
```
`GameModeSwitcher(FanController controller, AppSettings settings)`:
- `Tick(SensorSnapshot s, DateTime nowUtc)` on the poll thread **before** `FanController.Tick`:
  `gameActive` = `s.Values["fps.avg"]` is float ≥ **10**. Enter gaming after ≥ **5 s** continuously active;
  exit after ≥ **20 s** continuously inactive/null. On enter: `ApplyProfile(Gaming, deferSave: true)` if the
  profile exists and isn't already active; on exit: same with Desktop profile (if set; if null → nothing is
  applied, state still flips). `IsGaming`, `StatusText` ("Game mode: gaming (profile X since HH:mm)" /
  "Game mode: desktop" / "Game mode: off").
- Disabled → no transitions, `IsGaming` false. Missing profile name → transition still recorded, no apply,
  status notes "(profile not found)". Master switch off → profiles still load (desired state) but nothing is
  written — that's the controller's rule, unchanged.
- **Tracing:** `ApplyFrameTracing()` = `ShouldBeActive(...) || settings.GameModeEnabled` so the FPS reader runs
  whenever game mode is on (PresentMon child alive while enabled — documented in the UI text).
Fans window "Game mode" section: CheckBox, two ComboBoxes over `ProfileNames`, status line. Settings
change → `SettingsChange.GameMode` → App re-applies frame tracing.

**Tests.** Fixed-clock state machine: enter after 5 s, not at 4.9; exit after 20 s; flapping below
thresholds ignored; profiles applied once per transition; missing profile; disabled; `fps.avg` absent/NaN
treated inactive.

## 7. Inverted thresholds

`ThresholdRule.LowerIsWorse` (bool, default false). `ThresholdEvaluator`: when `LowerIsWorse` → `Crit` if
`v <= Crit`, `Warn` if `v <= Warn`. `ThresholdDefaults.Rules()` adds `{ Group=Game, Unit="fps", Warn=60,
Crit=30, LowerIsWorse=true }`. `SettingsService.Load` → `ThresholdDefaults.EnsureDefaults(rules)`: append
any default `(Group, Unit)` pair missing from the loaded list (existing files gain the FPS rule; user edits
untouched). `SettingsViewModel`: `FpsWarn`/`FpsCrit` with validation `Warn > Crit` for that row (message
"FPS: warn must be above crit"); XAML row "FPS (lower is worse)". Override creation (tile context menu) copies
`LowerIsWorse` from the matching group rule — find the creation site (`grep ThresholdOverrides` in
`Stats.App`/`Stats.Core`) and pass it through.

**Tests.** Evaluator inverted boundaries (60→Warn, 59.9→Warn, 30→Crit, 61→Normal); defaults contain the
rule; `EnsureDefaults` adds only missing pairs and never changes existing values; VM validation.

## 8. Curve source = max of several temperatures

`FanChannelPref.SourceMetricIds: List<string>` (new). Back-compat: `SettingsService.Load` migrates
`SourceMetricId` → `[SourceMetricId]` when the list is empty; `SourceMetricId` stays as the **first** id (kept
in sync by `FanController.SetSources`) so older builds still read something. `FanController.SetSources(id,
IEnumerable<string>)` (dedupe, drop blanks); `SetSource` becomes a shim (`SetSources` with one id). Source
value = **max** over the ids that are present and non-null/NaN in the snapshot; null only if none.
`FanChannelView.SourceMetricIds`. UI: the single ComboBox becomes an Expander "Sources (n)" containing a
`ListBox SelectionMode=Multiple` of `FanSourceSelection(Id, Label, IsSelected)`; `SourceTempText` shows the
max and the `LiveTemp` marker uses it. `CreateDefaultProfiles` (§5) writes single-id lists.

**Tests.** Controller max-of (two present → max; one null → other; all null → stale path); migration;
`SetSources` dedupe + first-id sync; VM selection round trip.

## Cross-cutting

- All new persisted fields have defaults so old `settings.json` loads unchanged; `SettingsService.Load`
  null-guards new collections.
- New `SettingsChange` members: `Hardware`, `GameMode`.
- Thread rule unchanged: only `FanController.Tick`/`RestoreAll`/`RecoverFromUncleanShutdown` (before the
  poller starts) and `GameModeSwitcher.Tick` (poll thread, via `ApplyProfile(deferSave:true)`) touch the
  backend.
- Tests stay in `tests/Stats.Core.Tests`, zero warnings.
- Out of scope: per-channel hysteresis/slew tuning, blocking enable on conflicts, live hardware
  re-discovery when the hardware setting changes, overlay status line, profile import/export.
