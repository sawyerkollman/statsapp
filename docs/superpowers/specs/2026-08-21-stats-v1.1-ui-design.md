# Stats v1.1 — UI Batch: Design Spec

**Date:** 2026-08-21
**Status:** Approved by user (design conversation, this date)
**Builds on:** v1 (`docs/superpowers/specs/2026-08-21-stats-dashboard-design.md`), merged to `master` at `113f6c4`.

## 1. Purpose

Raise the dashboard from "working" to "the monitor you actually keep open": faster visual scanning (threshold colors, gauges, core matrix), control over layout (reorder, sizes, rename, collapse), a settings UI instead of hand-editing JSON, a more capable overlay (click-through, hotkey, layout), richer history, and a benchmark-friendly peaks table.

## 2. Scope

### In scope

| # | Feature | Summary |
|---|---|---|
| 1 | Dark title bar | Dashboard + Peaks windows use DWM immersive dark mode. |
| 2 | Threshold colors | Value text amber at warn, red at crit. Rules per group+unit with per-metric overrides. Defaults: CPU °C 85/92, GPU °C 80/88, Load % 90/98. Applies to tiles, overlay values, peaks "Now", tray icon. |
| 3 | Dynamic tray icon + app icon | Tray icon renders CPU temp digits on a severity-colored background, refreshed when the value changes. Static `app.ico` for exe/taskbar. Tray menu gains Peaks and Settings. |
| 4 | Sparkline polish | Gradient fill under line, last-value dot, faint min/max guides, hover tooltip with value at cursor, small "2m"-style window tag. |
| 5 | Picker search & bulk | Search box filters by display/friendly/hardware name; per-group All/None; live value column while flyout open. |
| 6 | Tile kinds | Sparkline (default), Gauge (270° arc, Ryzen Master style), Bar (horizontal level bar, Afterburner style), Value (number only). Auto rule: Load % metrics, and any metric with an explicit max (`TilePref.Max` or `MetricLimits`) → Gauge; everything else → Sparkline (session max never triggers Auto→Gauge). Per-tile override via right-click menu. Plus the **Core Matrix** — not a `TileKind` but a dedicated CPU tile toggled by `ShowCoreMatrix`: one cell per core with load heat, clock, temp if present. |
| 7 | Settings tab | Flyout becomes Metrics \| Settings tabs. Settings: poll interval, history window, threshold editor, limits editor (PPT/TDC/EDC/GPU power), overlay orientation/font scale/opacity/click-through/hotkey, show core matrix. Live-apply + persist. |
| 8 | Friendly rename | Per-tile display name override; used on tiles, picker, overlay, peaks. |
| 9 | Reorder, sizes, collapse | Drag tile onto tile within a group to reorder (order persisted). Sizes S/M/L per tile. Group headers collapsible; Collapse all / Expand all. |
| 10 | Overlay: click-through + hotkey + layout | Click-through toggle (window ignores mouse), global hotkey toggles overlay (default Ctrl+Shift+O, editable), horizontal/vertical layout, font scale, severity colors. |
| 11 | History window | 2 / 5 / 15 / 60 minutes; ring buffer resized live keeping newest samples; applies to sparklines and L-size graphs. |
| 12 | Peaks window | Separate window: Name \| Now \| Min \| Avg \| Max for dashboard-selected metrics (toggle: all discovered). Reset session button clears session stats and buffers. Remembers bounds. |

### Out of scope

Alerts/notifications, CSV logging, per-process stats, custom color themes, freeform canvas layout, fan/OC control.

## 3. Architecture

Approach: extend the v1 MVVM tile system in place. All new logic that can be unit-tested lives in `Stats.Core` (settings model, threshold engine, core-matrix aggregation, reorder, resize, settings/picker ViewModels, hotkey parsing). `Stats.App` gains controls (ArcGauge, LevelBar, CoreMatrix, upgraded Sparkline), a `DataTemplateSelector`, a Peaks window, a tabbed flyout, Win32 helpers (dark title bar, click-through, global hotkey), and tray icon rendering.

### 3.1 Settings model additions (`Stats.Core.Settings.AppSettings`)

```
TilePrefs: Dictionary<string metricId, TilePref>
  TilePref { TileKind Kind = Auto; TileSize Size = M; string? Name; float? Max }
  enum TileKind { Auto, Sparkline, Gauge, Bar, Value }
  enum TileSize { S, M, L }
ThresholdRules: List<ThresholdRule>          // seeded defaults; editable
  ThresholdRule { MetricGroup Group; string Unit; float Warn; float Crit }
ThresholdOverrides: Dictionary<string metricId, ThresholdRule>   // Group/Unit ignored; Warn/Crit used
MetricLimits: Dictionary<string, float>      // (existing) PPT/TDC/EDC/GPU power limits
DashboardMetrics: List<string>               // (existing) NOW ALSO DEFINES TILE ORDER
CollapsedGroups: List<string>                // MetricGroup names
ShowCoreMatrix: bool = true
HistoryWindowMinutes: int = 2                // 2|5|15|60
OverlayOrientation: Horizontal|Vertical = Horizontal
OverlayFontScale: double = 1.0               // 0.8–1.6
OverlayClickThrough: bool = false
OverlayHotkey: string = "Ctrl+Shift+O"       // "" disables
PeaksLeft/Top/Width/Height: double?
```
All additions have defaults; a v1 settings.json loads without migration. Seeded `ThresholdRules` are written on first load if the list is empty.

### 3.2 Threshold engine (`Stats.Core.Metrics.ThresholdEvaluator`)

`Severity Evaluate(MetricDefinition def, float? value, AppSettings s)` → `Normal | Warn | Crit`.
Resolution: `ThresholdOverrides[def.Id]` → first `ThresholdRules` entry matching `(def.Group, def.Unit)` → Normal. Null/NaN → Normal. `value >= Crit` → Crit, else `>= Warn` → Warn.

### 3.3 ViewModels (`Stats.Core.ViewModels`)

- `MetricTileViewModel` gains: `Severity`, `Kind` (resolved: pref, else Auto rule), `Size`, `Max` (used by Gauge/Bar scale, resolved: pref → limit → 100 for `%` units → session max), `HistoryWindowTag` ("2m"), `DisplayName` honors friendly name, `LimitText` unchanged.
- `DashboardViewModel` gains: tiles built in `DashboardMetrics` order; `MoveTile(fromId, toId)`; `SetTileKind/SetTileSize/RenameTile/SetTileMax/RemoveTile(id, …)`; `CollapsedGroups` + `ToggleGroup(name)`, `CollapseAll/ExpandAll`; `CoreMatrix: CoreMatrixViewModel?` (null when disabled or no per-core metrics); `PickerFilter` string + `PickerView` filtering; `SelectAllInGroup/SelectNoneInGroup(group)`; `OpenPeaksRequested` event.
- `CoreMatrixViewModel`: from definitions, finds per-core metrics by regex `(?:CPU )?Core #(\d+)` across Load / Clock / Temperature; exposes `Cells: IReadOnlyList<CoreCell{Index, LoadText, ClockText, TempText, Load01}>`; `Refresh()`.
- `OverlayViewModel`: tiles carry `Severity`; orientation/font scale come from settings.
- `SettingsViewModel`: observable mirror of the editable settings; `Changed` event with a reason enum (`PollInterval, HistoryWindow, Thresholds, Limits, Overlay, Hotkey, CoreMatrix`); saves via callback.
- `PeaksViewModel`: rows `{Name, Now, Min, Avg, Max, Severity}` over selected (or all) metrics; `IncludeAll` toggle; `ResetSession` command → `MetricStore.ResetSession()`; `Refresh()`.
- `HotkeyParser` (Core): `"Ctrl+Shift+O"` ⇄ `(modifiers flags, key name)`; invalid → null.

### 3.4 History (`Stats.Core.Metrics`)

- `MetricHistory.Resize(int capacity)` — keeps the newest `min(count, capacity)` samples; session stats untouched. `ResetSession()` clears buffer and stats.
- `MetricStore.ResizeAll(capacity)`, `ResetSession()`.
- Capacity = `clamp(HistoryWindowMinutes * 60 / PollIntervalSeconds, 30, 3600)`; recomputed on either setting change.

### 3.5 App layer (`Stats.App`)

- **Controls:** `Sparkline` (upgraded: fill, dot, guides, hover tooltip), `ArcGauge`, `LevelBar`, `CoreMatrixView` (ItemsControl of cells, UniformGrid columns = 4 or 8), all severity-aware via `SeverityToBrushConverter` (Normal → TextPrimary, Warn → `#FFE6A23C`, Crit → `#FFE05A4F`).
- **TileTemplateSelector:** picks DataTemplate by `Kind` × `Size` (S always Value-style; L gives the kind more room).
- **DashboardWindow:** Expander-based group containers bound to collapsed state; drag-reorder (mouse down on tile → `DragDrop.DoDragDrop(metricId)`; drop on tile → `vm.MoveTile`); tile context menu; header gains Peaks, Settings (opens flyout on Settings tab), Collapse/Expand all; flyout = TabControl (Metrics | Settings); core matrix tile rendered first in CPU group when enabled.
- **PeaksWindow:** table + Reset session + "All metrics" toggle; dark title bar; bounds persisted.
- **OverlayWindow:** orientation/font scale bindings; click-through via `SetWindowLong(GWL_EXSTYLE)` toggling `WS_EX_TRANSPARENT` (drag disabled while on; turning it off restores drag).
- **Win32 helpers:** `DarkTitleBar.Apply(Window)` (`DwmSetWindowAttribute` attr 20; ignore failure), `ClickThrough.Set(Window, bool)`, `GlobalHotkey` (message-only HWND + `RegisterHotKey`; `Pressed` event; re-register on change; returns false on conflict → Settings shows "hotkey unavailable").
- **Tray:** `TrayIconRenderer.Render(int? cpuTemp, Severity)` → `System.Drawing.Icon` (32×32, rounded dark square, severity background tint, bold digits); previous HICON destroyed on swap; re-render only when text/severity changes. `app.ico` generated once by `tools/make-icon.ps1` (System.Drawing) and committed; csproj `<ApplicationIcon>`.
- **App.xaml.cs** wiring: settings change events → poller interval / store resize / overlay props / hotkey re-register / core matrix rebuild; peaks window lifecycle (single instance, hide on close); tray menu items.

### 3.6 Data flow

Unchanged core loop: poller (bg thread) → `Dispatcher.BeginInvoke` → `store.Apply` → `dashboardVm.RefreshAll()` (tiles + core matrix + picker live values if open) → `overlayVm.RefreshAll()` → `peaksVm.Refresh()` if window visible → tray icon/tooltip update.

## 4. Error handling

- Hotkey registration fails (conflict) → overlay still toggles via tray/button; Settings shows "Hotkey unavailable — in use by another app".
- DWM dark-titlebar call fails (old Windows) → ignored; default chrome.
- Tray icon render fails → falls back to static `app.ico`; GDI handles always destroyed.
- Click-through on + overlay off-screen → tray "Toggle overlay" and Settings remain reachable; Settings "Reset overlay position" button centers it.
- Drag-drop across groups or onto non-tile → ignored.
- `Resize` never drops the current value; `ResetSession` keeps the next tick's value as the new first sample.
- Per-core metrics absent (degraded mode / non-standard names) → core matrix hidden, no error.
- Any Settings input invalid (non-numeric limit, warn ≥ crit) → field outlined red, not applied.

## 5. Testing

Core unit tests: `ThresholdEvaluator` (override > rule > normal; boundaries; null), settings round-trip incl. new fields + v1-file migration, `DashboardViewModel.MoveTile` ordering + persistence, `MetricHistory.Resize/ResetSession`, `CoreMatrixViewModel` name parsing/aggregation, `SettingsViewModel` change reasons + validation, picker filter predicate, `HotkeyParser` round-trip/invalid. App controls/windows: build verification + user smoke test (UAC required, as in v1).

## 6. Success criteria

1. Hot CPU/GPU is obvious at a glance (amber/red) on dashboard, overlay, tray.
2. User can reorder, resize, rename, and switch tile kinds without touching JSON; all persists.
3. All v1 JSON-only settings (poll, limits) plus thresholds/overlay/history/hotkey editable in-app with live effect.
4. Overlay usable in-game: click-through + hotkey toggle.
5. Peaks window shows session min/avg/max for a benchmark run and resets on demand.
6. Dark chrome throughout; no white title bars.
