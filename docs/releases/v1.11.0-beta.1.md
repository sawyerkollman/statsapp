# v1.11.0-beta.1 release integration

Owner authorized publishing stable `v1.10.1` and prerelease `v1.11.0-beta.1`.
Stable tag targets `e285681` (updater-only backport); beta merges that master into `39aa3dd`.
The existing tag-triggered workflow builds installers and marks beta as prerelease, not latest.

## Integration

- Preserved beta layouts, lock/undo, recordings, comparison, processes and persistent alert context.
- Brought in stable notification settings/policy, shell-safe notification text and tray click behavior.
- Kept the snapshot timestamp and context capture when combining notification and alert-history paths.
- Review found an alert-row decimal-format regression; passing the event format fixes it, with an
  F1 export/load regression test. Fan/poller shutdown ordering and hardware ownership are unchanged.
- Used existing native WPF/updater code and dependencies; no release infrastructure added.

## Routing

Existing routing preflight/configuration reused. Two explicit `stats_ui_terra` workers resolved disjoint
Core and UI/preview files; parent owned composition root/docs/git. `stats_ui_reviewer` independently
reviewed the integrated source and `stats_ui_validator` handled isolated WPF evidence. Effective model
metadata is unobservable. One bounded Core repair, no delegation by workers or dependency changes.

## User flow

Install `v1.10.1`, then select Settings > System > Receive beta updates and check for updates.
Beta is opt-in. Turning it off waits for an equal/newer stable release; it does not downgrade.
Later beta promotion remains a separate merge/release decision.
